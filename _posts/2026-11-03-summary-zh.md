### [Linux IPv4 TCP 高危漏洞更新提醒](https://telegram.me/zaihuapd/44866) ⭐️ 8.0/10

一则 Telegram 安全提醒称，Linux 内核 IPv4 TCP 存在高危释放后使用漏洞 CVE-2026-98432，攻击者可能无需认证或用户交互即可从网络侧触发并实现远程代码执行。帖子援引 Anthropic 公布的 MPTCP 监听端口 RCE 利用示例，并称该问题不限于 MPTCP 场景。Go 官方安全团队被引述提示，自 Go 1.24 起，Linux 上的监听套接字默认启用 MPTCP，因此 Go 服务可能默认暴露于相关攻击面，即使未监听 MPTCP 端口也可能受到同类攻击。当前材料未提供受影响的修复内核版本、原始公告或完整技术分析，具体影响范围、补丁状态及缓解措施仍需官方来源核实。

telegram · zaihuapd · 11月3日 02:37

**「背景」** 释放后使用（use-after-free，UAF）是指程序在对象或内存已经释放后仍继续访问，可能造成信息泄露、崩溃或代码执行；本条提醒称 CVE-2026-98432 是 Linux IPv4 TCP 路径中的此类高危漏洞。MPTCP 是 TCP 的多路径扩展，Go 1.24 起在 Linux 上的监听套接字默认启用 MPTCP，因此相关 Go 服务即使未显式使用 MPTCP 监听，也可能受到影响，具体风险仍取决于内核版本、配置和补丁状态。

**「实际影响与处置重点」** 运行 Linux 内核并暴露 IPv4 TCP 服务的组织可能面临未认证网络攻击、释放后使用乃至远程代码执行，其中 Go 1.24 及以上版本在 Linux 上默认启用 MPTCP 的监听服务风险尤其突出，即使未启用 MPTCP 的服务也可能受同类路径影响，应尽快核查暴露面并安装发行版提供的修复内核。由于原帖未给出受影响版本、补丁版本或一手公告，社区提出的防火墙前置拦截及 Ubuntu 等发行版的修复优先级仍需等待官方确认。

**「社区对缓解与修复的讨论」** 评论者提出可通过 iptables 或 nftables 在 raw PREROUTING 阶段提前丢弃相关 IPv4 TCP 流量，但有人援引 RHEL 的说法称此类缓解只能降低暴露、不能完全阻止漏洞，且没有提供清晰解释。争议主要集中在 Ubuntu 的修复延迟及其仅评为 High 而非 Critical 的优先级，此外，消费级路由器长期缺少内核安全更新以及 LLM 降低漏洞利用门槛也引发担忧。
