### [Wine 成功移植至 OpenBSD](https://marc.info/?l=openbsd-ports&amp;m=179236125692175) ⭐️ 6.0/10

Wine 的 Windows 兼容性层已完成向 OpenBSD 的移植，开发者针对该系统安全导向的架构做出了多项底层修改，包括为 %gs 段寄存器添加存根处理以及对 SIGUSR1 等信号机制的重新适配。在 Linux 上由于内核已正确设置 %gs，这些新增存根不会参与编译；而 SIGUSR1 的替代实现在其他系统上虽然可以运行，但效率较低。开发者明确表示，所有 OpenBSD 特有改动均以条件编译限定在 OpenBSD 平台，这样做主要是为了简化开发流程并清晰标记差异，并没有将这部分专有代码合并到上游 Wine 的计划。移植成果已在社区分享的多段游戏运行视频中得到验证，涵盖《极乐迪斯科》《Hollow Knight》《Prey 2017》《死亡搁浅》以及《巫师 3：重制版》等 Windows 游戏。

hackernews · iamnothere · 10月19日 13:35 · [社区讨论](https://news.ycombinator.com/item?id=50152307)

**「背景」** Wine 是一款开源的 Windows 应用兼容层，通常在 Linux 等类 Unix 系统上运行 Windows 程序。OpenBSD 是一个以安全为设计目标的类 Unix 操作系统，其内核不允许用户态进程直接设置 %gs 等段寄存器，这与 Linux 通过 arch\_prctl\(ARCH\_SET\_GS\) 让用户态自行配置段基址的做法形成对比，也成为将 Wine 移植到 OpenBSD 的主要技术障碍。在此次移植中，开发者选择在软件层面模拟 %gs 前缀，并加入 OpenBSD 特定的信号处理（如对 SIGUSR1 的利用）等修改，从而使 Wine 在不破坏 OpenBSD 安全模型的前提下得以运行。

**「影响」** 这一进展首次让 OpenBSD 用户能够在该系统上原生运行 Windows 应用程序与游戏，主要惠及希望在保留 OpenBSD 安全特性的同时仍需使用 Windows 兼容软件的用户和开发者。

**「社区讨论」** 社区关注点集中在实际游戏运行的可用性证据上，开发者分享了多条游戏实机视频作为验证，并进一步解释了改动被有意保留为 OpenBSD 专有、不太可能合并到上游 Wine 的原因。讨论中还出现了对开发者姓氏 &quot;Frohwein&quot;（德语中近似 &quot;欢乐之酒&quot;）的趣味观察，以及将项目顺势命名为 &quot;Port&quot;（兼具&quot;移植&quot;与&quot;葡萄酒&quot;双关含义）的幽默建议。
