### [Ladybird 发布首个可安装 Alpha 版](https://simonwillison.net/2026/Nov/23/ladybird/) ⭐️ 8.0/10

Ladybird 于 2026 年 11 月 23 日发布首个可安装的 Alpha 版本，支持 macOS 和 Linux，用户无需自行编译即可下载。该浏览器自主实现了 HTML 解析、CSS、布局、JavaScript 和 WebAssembly 等大部分核心 Web 技术，同时复用 HarfBuzz 文本整形、Skia 2D 图形、FFmpeg 视频和 SQLite，并以多进程方式隔离标签页。Simon Willison 实测发现多数网站能够正常加载，基于 WebAssembly 的 FFmpeg 工具和 Pyodide REPL 均可运行，但依赖 Service Worker 与 Web Worker 协作的 Datasette Lite 因缺少 \`navigator.serviceWorker.startMessages\` 而失败；项目也明确警告 Alpha 尚不支持部分网站并可能偶发崩溃。10 月，团队使用 AI 编码代理补齐 Web Platform Tests 功能，新增 75,650 个通过的子测试，在约 225 万项测试中超过 Safari；同期新的 JavaScript JIT、样式与布局线程化以及 WebAssembly 代码还使 JetStream 3 WASM 基准获得 7 倍提升。项目此前还使用 Claude Code 和 Codex，在两周内将 LibJS 的部分代码从 C++ 移植为 25,000 行 Rust。

rss · Simon Willison · 11月23日 21:46

**「项目背景」** Ladybird 与 SerenityOS 关系密切，部分浏览器代码来自这个更早、更雄心的操作系统项目。它的核心目标是以自研实现承载 Web 标准，同时继续复用适合生产环境的通用基础库。

**「实际影响」** macOS 和 Linux 用户由此获得无需编译即可参与测试的独立浏览器，开发者也多了提交兼容性问题和崩溃报告的反馈渠道；现阶段的主要收益是扩大测试覆盖，而非获得可立即替代主流浏览器的稳定产品。

**「社区反馈」** 试用者普遍对复杂新闻站点、Proxmox 及 NoVNC 页面的正常渲染表示惊喜，少数人提到滚动略不顺畅，也有人开始认真考虑将其作为日常浏览器。另一部分评论担忧指纹追踪、权限粒度、标签页活动状态暴露和 Alpha 阶段的安全风险，并认为复用 SQLite、Skia 等成熟库削弱了早期全自研的愿景。

### [Codex2api 疑似遭供应链投毒](https://github.com/WormW/codex2api-incident-2026-11) ⭐️ 8.0/10

据 Telegram 转述及所链接的事件复盘，Codex2api 作者账号疑似被黑，攻击者绕过 main 分支直接推送 tag，使 Release 构建流程产出带后门版本，报告将 v3.1.10–v3.1.12 列为受影响范围。报告称，v3.1.11 移除了鉴权，可导致无密码远程执行命令，另有 workflow 将单个仓库的 16 个 GitHub Actions secrets 外传，波及该账号下至少 21 个仓库。已安装或更新上述三个版本的用户应立即停用相关版本、回退至 v3.1.9，并轮换 GitHub token、SSH key、数据库凭据及 DeepSeek 等相关密钥。当前信息主要来自 Telegram 转述，事件范围与具体受影响版本仍应以原始报告和上游仓库公告进一步核验。

telegram · zaihuapd · 11月23日 11:21

**「GitHub Actions 供应链投毒背景」** GitHub Actions 的 Release 工作流可由版本 tag 自动触发，因此攻击者即使不改动 main 分支，也能通过恶意 tag 生成并分发受污染的发布包。Codex2api 事件中，报告同时指向发布包内的无鉴权命令执行逻辑，以及构建工作流读取仓库 secrets 并外传凭据的路径，使风险可能从单个安装者扩展至同一账号下的其他仓库。

**「实际影响」** 若事件报告属实，已安装或更新至 v3.1.10–v3.1.12 的用户面临无鉴权远程命令执行及凭据外泄风险，并可能波及作者同账号下至少 21 个仓库和其中的 16 个 GitHub Actions secrets。受影响用户应立即停用相关版本、回退至 v3.1.9，并轮换 GitHub token、SSH 密钥、数据库及 DeepSeek 等相关凭据；但目前证据主要来自 Telegram 转述，实际影响范围仍待独立核验。

Ai2 发布 RoboTrack，这是一套面向真实机器人操作的点跟踪基准与训练数据套件，同时公开模型、技术报告、数据、代码和项目资源，旨在帮助机器人在抓取器遮挡、杂乱场景和视角变化下持续跟踪夹爪及被操作对象上的指定点。RoboTrack-Bench 汇集 DROID、Ego-Exo4D、MolmoAct 2 和 EgoVerse 的 307 段人工标注视频与 2,522 条经逐帧复核的轨迹，其中 33 对视频采用同步双视角，覆盖机器人与人手、静态及操纵物体，以及多种第一和第三人称场景。通过扩展 MolmoSpaces，团队还构建了面向机器人操作、包含约 1,500 万条密集点轨迹的合成训练集 RoboTrack-15M，并发布由 AllTracker 微调的 RoboTracker 和基于 CoWTracker 训练的 RoboTracker-Warp。评测显示，四个主流跟踪器在 RoboTrack-Bench 上的平均 Jaccard（AJ）均比 RoboTAP 低 3.0 至 6.6 点，其中 CoWTracker 从 70.5 降至 63.9；额外使用 1,500 万段真实视频训练的 BootsTAPNext 虽在 RoboTrack-Bench 上提高 5.1 AJ，却在模拟基准 RGB-Stacking 上下降 9.5 AJ，表明现有基准中的领先表现未必能迁移到真实操作。两个新模型相对各自已发布基线均提高了三个机器人基准的平均 AJ，RoboTracker-Warp 在所评五个基准中的四个达到领先，并已用于真实机器人的湿实验移液操作；评测采用作者统一协议，AllTracker 发布代码中的一个评分错误已被修复，因此部分数值与原论文略有差异。

rss · Hugging Face Blog · 11月23日 17:20

**「背景」** 点跟踪技术根据视频首帧中的一个位置，估算同一物理点在后续帧中的位置，包括物体被遮挡以及重新出现后的轨迹。这些轨迹可为机器人从演示中学习、规划动作和提供执行反馈提供空间信息。为检验现有点跟踪器能否应对真实机器人交互中的杂乱背景、夹爪遮挡和视角变化，RoboTrack 同时构建了真实操作视频评测集与面向机器人操作的合成训练数据。

**「实际影响」** 真实机器人操作开发者在选择点跟踪器时，需要用 RoboTrack-Bench 重新验证模型，而不能只看既有基准排名：四种受测跟踪器在该基准上的 AJ 均比 RoboTAP 低 3.0–6.6，而 RoboTrack-15M 合成训练数据已显示能提升真实操作视频及部分其他跟踪基准的表现。

### [ERNIE 5.5 Flash 的 vLLM 首发支持](https://vllm.ai/blog/2026-11-24-ernie-5-5-flash-preview) ⭐️ 8.0/10

rss · vLLM Blog · 11月24日 00:00

**「背景」** ERNIE 5.5 Flash Preview 是 2800 亿总参数、每 token 激活 140 亿的稀疏 MoE，支持 100 万 token 上下文；vLLM 适配需同时解决长上下文索引、权重搬运和小算子带来的显存往返、启动开销。

**「方案」** 团队为 43 层模型开发专用融合内核：把 VHA 混合预折叠并合入 FP8 量化，合并多路由器 GEMM 与 Top-10 路由，单遍完成 MultiMax 和门控；作者称较朴素实现快 1.55～6.53 倍。FlashIndexer 仅按当前 token 路由少量索引头，再阈值预筛 Top-k，不改下游稀疏注意力接口；作者称在 100 万上下文下正文测得 1.4 倍加速，但摘要的“40%”口径未获解释。路由专家用训练与推理一致的 QAT 存为 MXFP4 W4A8，其余权重及 KV cache 用 FP8；三层 DSpark 草稿模型经多阶段训练和在线蒸馏后，作者称在编码及 Agent 负载上平均接受长度超过 4.0，每步最多提议 7 个 token。部署以独立插件替代 vLLM 分支，同一环境安装官方 vllm==0.32.0 与插件即可；插件主要注册 ERNIE 架构、配置与解析器，并行、PD 分离、KV 卸载及 OpenAI 服务仍复用 vLLM。

**「启示」** 其主张是，模型专用融合、稀疏路由与量化协同可支撑新架构首发并持续迭代；但性能主要来自厂商自报，尚缺硬件、基线和方法学。
