### [PostgreSQL 19 Adds Standby Read-Your-Writes Consistency](https://simonwillison.net/2026/Nov/19/postgresql-19/) ⭐️ 8.0/10

PostgreSQL 19 was released in November 2026, two months later than the project’s usual September schedule; Simon Willison attributes the delay mainly to fixes addressing issues amid an ongoing wave of AI-reported vulnerabilities. Its standout addition is \`WAIT FOR LSN\`, which lets a session connected to a standby wait until write-ahead log replay has reached a specified log sequence number before reading, providing read-your-writes behavior for data just written on the primary. An application can capture \`pg\_current\_wal\_insert\_lsn\(\)\` after a write, save the LSN, and later execute \`WAIT FOR LSN &\#x27;0/0306EE20&\#x27; WITH \(TIMEOUT &\#x27;0.1s&\#x27;\)\` before querying the standby; the timeout is optional, and exceeding it produces an error. The article focuses on this feature and MediaWiki’s hand-rolled MySQL equivalents, \`WAIT\_FOR\_EXECUTED\_GTID\_SET\(\)\` and \`SOURCE\_POS\_WAIT\(\)\`, rather than surveying PostgreSQL 19’s other changes.

rss · Simon Willison · Nov 19, 20:43

**「WAL Replication and Read Consistency」** PostgreSQL standby servers follow a primary by replaying its write-ahead log \(WAL\), with each position in that byte stream identified by a log sequence number \(LSN\). Because a standby can lag behind the primary, an immediate read may otherwise return stale data; PostgreSQL 19’s WAIT FOR LSN command blocks until the standby has replayed WAL through a requested LSN, with an optional timeout. Applications such as MediaWiki previously implemented similar consistency waits with MySQL replication coordinates, making this feature a PostgreSQL-native equivalent of that hand-built pattern.

**「Impact」** Applications using PostgreSQL 19 with asynchronous standbys can use \`WAIT FOR LSN\` to block reads until the replica has replayed the relevant write, providing read-your-writes consistency and reducing the need for custom replica-catch-up logic. If the standby cannot reach the requested LSN before an optional timeout, the command returns an error rather than exposing potentially stale data.
