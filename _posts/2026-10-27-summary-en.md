### [webframe evaluated for scraping and sandboxing](https://simonwillison.net/2026/Oct/26/webframe-evaluation/) ⭐️ 6.0/10

Jeff Lindsay&\#x27;s webframe is a compact Go program that runs a URL or local file in a hidden system WebView, sends console.log output to standard output, and reports exceptions on standard error. It uses the glaze library to access WKWebView on macOS, WebKitGTK on Linux, and WebView2 on Windows, avoiding a bundled browser engine and a Playwright dependency. Simon Willison commissioned Claude Opus 5.5 to exercise the tool, build exploratory prototypes, and assess it for web scraping patterns similar to shot-scraper JavaScript and for sandboxing. The available post provides the evaluation prompt but ends before the report&\#x27;s detailed findings or measurable results, so it does not establish comparative performance or security effectiveness.

rss · Simon Willison · Oct 26, 16:15

**「Background」** WebView-based tools execute web content through a platform-provided rendering engine rather than bundling a complete browser. Webframe is written in Go on top of Glaze, a CGo-free WebView toolkit, and uses WKWebView on macOS, WebKitGTK on Linux, or WebView2 on Windows, allowing it to expose a hidden page runtime for scraping or sandbox-like experiments without shipping its own browser engine.

**「Practical implications」** For Go developers building lightweight scraping or controlled page-execution tools, webframe runs pages in hidden platform WebViews and sends console output and exceptions to standard streams without bundling a browser engine or requiring Playwright, reducing deployment overhead but requiring WKWebView on macOS, WebKitGTK on Linux, or WebView2 on Windows. The supplied evaluation excerpt does not demonstrate that the WebView boundary safely isolates untrusted code, so webframe should not yet be treated as a hardened security sandbox.
